# Публикация обновления RMRP Помощника

Пользовательское приложение больше не использует GitHub Releases для поиска обновлений. Оно читает публичный JSON `latest.json` из Supabase Storage.

## Первичная настройка Supabase

1. Откройте проект Supabase → **Storage** → **New bucket**.
2. Название: `app-releases`.
3. Включите **Public bucket** (публичное чтение файлов).
4. Не включайте публичную загрузку/изменение файлов. Загружать релизы должен только владелец проекта через Dashboard.
5. В `app/rmrp/config.py` проверьте `UPDATE_MANIFEST_URL` — он уже указывает на bucket этого проекта.

## Выпуск новой версии

1. Измените `app/rmrp/version.py` и укажите новую версию.
2. Обновите `RELEASE_NOTES.md`.
3. Запустите `build_windows.bat` на Windows с Python 3.12 и Inno Setup 6.
4. Выполните `python installer/prepare_release.py`.
5. В Supabase → Storage → `app-releases` загрузите новый `RMRP-Pomoshnik-Setup-X.Y.Z.exe`.
6. Последним загрузите `release/latest.json`, подтвердив перезапись старого файла.

Порядок важен: пока новый EXE не загружен, манифест должен указывать на предыдущую версию. Публикация `latest.json` последней не позволит клиентам увидеть неполный релиз.

## Формат манифеста

`latest.json` содержит версию, заметки, имя установщика, публичный HTTPS URL, размер файла и SHA-256. Клиент проверяет разрешённый домен Supabase, имя EXE, размер и SHA-256 до запуска установщика.

## Безопасность

- В клиенте разрешено хранить только Supabase publishable key; `service_role` и секретные ключи нельзя включать в приложение.
- Bucket должен быть публичным только на чтение. Не создавайте политики INSERT/UPDATE/DELETE для `anon`.
- SHA-256 обнаруживает повреждение файла, но сам по себе не является цифровой подписью манифеста. Для более сильной защиты следующий этап — подпись релизов Ed25519 и проверка подписи встроенным публичным ключом.
- Автоустановка выполняется только в собранной Windows-версии. В режиме запуска из исходников можно проверить обновление, но установка автоматически не запускается.


## Автоматическая сборка и публикация через GitHub Actions

В репозитории откройте **Settings → Secrets and variables → Actions** и добавьте два Repository secrets:

- `SUPABASE_URL` — URL проекта Supabase (например, `https://<project-ref>.supabase.co`).
- `SUPABASE_SERVICE_ROLE_KEY` — secret/service_role key проекта. Он хранится только в GitHub Secrets и никогда не встраивается в приложение или архив исходников.

После этого отправьте в GitHub тег версии, совпадающий с `app/rmrp/version.py`, например `v3.1.5`. Workflow `.github/workflows/publish-windows.yml` соберёт EXE и Setup на Windows, создаст манифест и загрузит установщик в bucket `app-releases`, а `latest.json` опубликует последним.

**Важно:** не добавляйте service_role key в `config.py`, `.env` приложения, публичные файлы или сообщения. Если ключ когда-либо попадёт в репозиторий, немедленно ротируйте его в Supabase.
