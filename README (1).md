# 🛡️ RMRP Помощник 3.1.5

**Законодательство, обучение, тесты и управление для RMRP.** by Kinzec X WOLF

## Возможности приложения

- Новый интерфейс по макету: боковая навигация, главная с плитками, «Последнее изученное», объявления.
- **Законы:** карточки с числом глав и статей, просмотр закона с главами, вкладки «Содержание / О законе / Версии», подсветка найденных слов, копирование и избранное.
- **Поиск** по номеру («статья 12», «УК 228»), названию и тексту — с морфологией и ранжированием, история запросов.
- **Нейросеть (ИИ)** — чат, отвечающий цитатами из базы с источником и кнопкой «Открыть статью». Не выдумывает: если материала нет — так и говорит.
- **Тесты:** вкладки «Все / Пройденные / Избранные», сложность звёздами, прохождение в окне, разбор ответов.
- **Админ-панель:** пользователи со статусом Online, роли, жалобы, тесты, законы, объявления, журнал, скример (только Основатель, только с согласия получателя).
- **Discord Rich Presence** (окно настройки как на макете, живой предпросмотр).
- **Оверлей в игре** по F10: быстрые разделы и мгновенный поиск по статьям.
- **Гостевой режим**, вход по логину или email, «Запомнить меня», восстановление пароля.
- Профиль со статистикой, страница «История» (статьи, поиск, вопросы ИИ, тесты).
- Надёжность: фоновые запросы (интерфейс не «замирает»), автообновление токена, постраничная загрузка (>1000 строк), безопасная синхронизация законов (сначала апсерт, потом удаление устаревшего — закон не остаётся пустым при сбое).

## Установка базы (Supabase → SQL Editor, по порядку)

1. `rmrp_database.sql`
2. `release_migration.sql`
3. **`migration_v2.sql`**
4. **`migration_v2_2.sql`** ← новое: права админа/основателя на удаление жалоб, законов, тестов
5. **`migration_v2_3.sql`** ← новое: статистика запросов для сводки админки
6. `RMRP_PRANKS_AND_PROFILE.sql` (если ещё не выполняли)
7. `RMRP_LAWS_SYNC.sql`
8. `FOUNDER_SETUP.sql` — заменить `EMAIL_ОСНОВАТЕЛЯ` на ваш email
9. **`migration_v2_6.sql`** ← новое: смена паролей, email и ников Основателем и администраторами

Затем в приложении: **Админ-панель → Законодательство → Синхронизировать RMRP** (загрузит статьи вместе с главами). Другие законы добавляются кнопкой «Добавить закон» со ссылкой на тему форума — они синхронизируются вместе с остальными.

## Возможности, добавленные в версии 2.6 — смена паролей, email и ников из базы

Выполните **`migration_v2_6.sql`** (Supabase → SQL Editor, после `migration_v2_5.sql`; можно запускать повторно). Он добавляет функции `admin_set_password`, `admin_set_email`, `admin_set_nickname`, `admin_get_email` с проверкой роли и записью в журнал `audit_logs` (пароли в журнал не пишутся).

- **Основатель** меняет данные любого аккаунта. **Администратор** — свои и аккаунты модераторов, премиум-пользователей и пользователей; аккаунты Основателя и других администраторов ему недоступны (иначе через смену чужого пароля можно захватить Основателя).
- Вызываются через Supabase RPC под вошедшим Основателем/админом (примеры в шапке файла). Из SQL Editor функции не вызываются, там нет вошедшего пользователя: для ручной правки в самом редакторе в конце файла есть готовые шаблоны.
- После смены пароля или email чужого аккаунта его сессии закрываются, человеку придётся войти заново.

## Возможности, добавленные в версии 2.5

Выполните **`migration_v2_5.sql`** (Supabase → SQL Editor, после `migration_v2_3.sql`; скрипт можно запускать повторно). Он создаёт таблицу памяток, публичное хранилище `memo-images` для фото, функции `memos_feed` и `app_team` и общую настройку цветов ролей.

- **Автовход:** токен сессии лежит в `%APPDATA%\RMRP-Pomoshnik\session.dat` (шифрован DPAPI, привязан к компьютеру и пользователю Windows). Удалить файл = забыть вход.
- **Памятки:** кто публикует, задаёт функция `can_publish_memos()` в SQL (по умолчанию FOUNDER и ADMIN; добавьте `'MODERATOR'`, если нужно и модераторам).
- **Цвета ролей:** Настройки → «Цвета ролей» (только Основатель), хранятся в `app_settings.role_colors`.

## Оверлей

Горячая клавиша по умолчанию **F10** (меняется в настройках). Работает поверх игры в оконном и безрамочном режимах; в «настоящем» полноэкранном режиме Windows не позволяет показывать чужие окна.

## Автообновление через Supabase Storage

Клиент проверяет `latest.json` в публичном на чтение bucket `app-releases` проекта Supabase. GitHub для доставки обновлений больше не нужен. Проверка выполняется при запуске и раз в 6 часов; EXE скачивается по HTTPS, сверяется по размеру и SHA-256, затем запускается собственный установщик Inno Setup в тихом режиме.

**Первичная настройка и публикация:** см. [`release/README.md`](release/README.md). На компьютере разработчика запустите `build_windows.bat`: он соберёт приложение и Setup.exe, затем создаст `release/latest.json`. Загрузите EXE в Supabase Storage, а `latest.json` — последним. Публичный bucket нужен только для чтения; загрузка выполняется владельцем проекта через Dashboard.

Первую сборку 3.0.1 нужно установить вручную поверх 3.0.0. После этого клиенты получают последующие версии автоматически. Автоустановка доступна в собранной Windows-версии.

## Сборка

**На своём компьютере (Windows):** двойной щелчок по `build_windows.bat`. Скрипт установит PyInstaller и Pillow, соберёт EXE, найдёт (или через winget поставит) Inno Setup 6 и создаст установщик `installer\output\RMRP-Pomoshnik-Setup-X.Y.Z.exe` и манифест `release\latest.json`. Нужен Python 3.10+.

Локальные тесты: `python -m unittest discover -s tests` и `python tests/smoke_gui.py`.

## Безопасность

Publishable key в клиенте — намеренно. **Secret/service_role ключ в приложение добавлять нельзя.** Ограничения доступа обеспечивает RLS Supabase.
Функция `login_email` (вход по логину) возвращает email по логину; если это нежелательно — удалите её из `migration_v2.sql`, вход останется по email.

## Версия 3.1.3 — защита синхронизации законодательства

- Перед импортом проверяются номера статей, отсутствие пустых текстов и минимальный объём выгрузки.
- Если форум отдаёт менее 70% ранее загруженных статей, импорт конкретного закона отменяется до любых изменений в базе. Это защищает существующую редакцию от частичной или антибот-страницы.
- Список прежних статей читается до записи; устаревшие статьи удаляются только после успешного апсерта всех новых статей.
- Команда «подробнее» в чате нейросети теперь показывает полный текст статьи, а не обрезает его на 1800 символах.


## Публикация обновлений 3.1.5+

Автообновление уже встроено в клиент. Для автоматической сборки и публикации релизов настройте GitHub Secrets `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`, затем отправляйте тег `vX.Y.Z`, совпадающий с `app/rmrp/version.py`. Подробности — в `release/README.md`.
