# Архитектура RMRP Помощника 3.0.1

## Компоненты

- **Windows Desktop** — Python/Tkinter-приложение, поставляемое как единый EXE через PyInstaller.
- **Установщик** — Inno Setup 6, создаёт ярлыки, устанавливает приложение и поддерживает тихий режим обновления.
- **Supabase Auth** — регистрация, вход, восстановление сессии и роли пользователей.
- **Supabase Database** — профили, законодательство, статьи, тесты, результаты, избранное, история, объявления и административные данные.
- **Supabase Storage / `app-releases`** — публичное чтение манифеста и установщиков; запись только владельцем проекта через Supabase Dashboard.
- **Updater** — проверка манифеста при запуске и далее каждые шесть часов, скачивание установщика, проверка размера и SHA-256, тихий запуск установщика.

## Поток обновления

1. Разработчик увеличивает `app/rmrp/version.py`, обновляет `RELEASE_NOTES.md` и запускает `build_windows.bat` на Windows.
2. Скрипт собирает `RMRP_Pomoshnik.exe`, затем `RMRP-Pomoshnik-Setup-X.Y.Z.exe`.
3. `installer/prepare_release.py` вычисляет SHA-256 и создаёт `release/latest.json`.
4. Разработчик загружает EXE в публичный на чтение bucket `app-releases`.
5. После загрузки EXE публикует `latest.json` последним.
6. Установленное приложение видит более новую версию, показывает заметки, скачивает установщик и проверяет его до запуска.
7. Inno Setup закрывает приложение, обновляет файлы и запускает новую версию.

## Границы безопасности

- Клиент содержит только Supabase publishable key. Service-role/secret key в клиент не помещается.
- Публичный bucket даёт право чтения, но не право публикации. Не выдавайте `anon` разрешения INSERT, UPDATE или DELETE в Storage.
- Манифест и установщик загружаются по HTTPS. SHA-256 защищает от повреждения/подмены файла относительно полученного манифеста, но не заменяет цифровую подпись самого манифеста.
- Следующее усиление защиты — подпись манифеста Ed25519 с закрытым ключом вне приложения и закреплённым публичным ключом в клиенте.
- Supabase RLS остаётся обязательной границей доступа к пользовательским данным и административным операциям.

## Важное ограничение перехода

Сборки 3.0.0 были собраны со старым механизмом обновлений и не умеют читать новый Supabase-манифест. Поэтому переходная версия 3.0.1 устанавливается один раз вручную. Начиная с 3.0.1, новые релизы доставляются через Supabase Storage автоматически.
